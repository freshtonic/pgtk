## Immediate blocker: strict statement parsing

The pg-sql library suite currently reports:

```text
1080 passed; 2 failed; 2 ignored
```

Both failures have one root cause:

- `ast::shared::expr::tests::parse_json_timestamp_cast_before_unique_keys`
- `ast::shared::expr::tests::type_name_preserves_legacy_fixed_variants_and_json_ident`

The second test reaches the first regression through its cast-type round-trip helper. The minimal
failing input is:

```sql
JSON('2000-01-01'::timestamp WITH UNIQUE KEYS)
```

`DateTimeCastType` contains `Option<TimeZoneQualifier>`. The optional decision sees `WITH`,
commits to `WITH TIME ZONE`, and then fails at `UNIQUE` instead of leaving `WITH UNIQUE KEYS` for
the enclosing JSON constructor. This is a suffix-sensitive optional-viability problem: the first
token alone does not prove that the optional qualifier is viable. It should be minimized and
fixed as a general Recursa generated-parser capability rather than with a PostgreSQL-specific
handwritten exception.

Reproduction:

```bash
cargo test --package pg-sql --lib \
  ast::shared::expr::tests::parse_json_timestamp_cast_before_unique_keys -- --exact
```

Full library check:

```bash
cargo test --package pg-sql --lib
```

## Build and diagnostic problems

Recursa generation is CPU-bound and dominates local feedback time while memory use remains
stable. Current measurements on this checkout are:

- Diagram-enabled `cargo doc --workspace --all-features --no-deps`: 3m36s.
- `cargo test --package pg-sql --lib`: 2m23s compilation, 3.93s test execution.
- Before diagrams were enabled, `cargo build --workspace --all-features`: 2m26s.

This behavior has not been proved to be an infinite loop. Earlier path-level Pratt cutoff work
removed a more severe expansion, but generation remains slow enough to make narrow test cycles
expensive. When diagnosing it, profile the pg-sql build script or Recursa analysis directly;
profiling test execution will miss the cost.

The Recursa diagnostic transport fix reduced Cargo output from 318 warning directives to 225 by
removing 93 indistinguishable repeats. The remaining 225 are distinct advisory findings:

- 196 `RCA0300` nullable-use/caller-FOLLOW overlap warnings.
- 29 `RCA0301` Pratt-use/caller-FOLLOW overlap warnings.

These warnings do not currently fail builds, but they violate the port plan's warning-free
Rustdoc/CI completion gate, obscure actual failures, and make terminal output difficult to audit.
Do not remove them with another presentation-only deduplication pass: each remaining line is
distinct. Determine which findings represent real grammar ambiguity, which are conservative
analysis false positives, and which need a reviewed suppression mechanism backed by proof.

Parse failures are also excessively verbose because `ParseError` debug output prints the full
`GrammarInfo` token and atom tables. The focused failure above produces a very large panic even
though its useful fact is only that `UNIQUE` was encountered after committing to the time-zone
qualifier. This is a separate diagnostic-usability problem.
