# PostgreSQL 17.9 port status — 2026-09-01

This supersedes the stalled-state sections of `handoff-2026-08-31.md`.

## Resolved

The strict-statement blocker is fixed as a general Recursa capability, not a
PostgreSQL exception. Recursa now freezes a suffix-proving optional-viability
decision when an optional element's FIRST overlaps caller FOLLOW and the
element's bounded prefix language is closed: the generated parser walks the
element's own prefixes (`WITH TIME ZONE`), consumes only on a proven match,
and returns diverging input (`WITH UNIQUE KEYS`) to the caller. Open element
languages (Pratt continuations, depth-cut sequences) keep the greedy legacy
selector because their bounded sequences approximate the real language.

  2 ignored. Both handoff regressions pass.
- The last diagnostic-outcome accepted legacy gap (join.sql:171,

  it round-trips; erased `optional(...)` groups cannot.
- Workspace Clippy and `cargo fmt` are clean. The 225 RCA0300/0301 analysis

Recursa `main` additionally carries the semantic generation identity (neutral

## Issue #10 attempt (2026-09-01): blocked by two Recursa gaps

The strict `parse_sql` document interface cannot land at the Recursa pin
`c4e7f3f`. No pg-sql workaround exists inside the derivation principles.
The attempt found two capability gaps and validated the full design for the
moment they close. All findings below come from a minimal fixture crate that
depends only on the pinned Recursa.

### Gap 1 (hard blocker): explorer generation panics on shared content bases

Enable `explorer` on `recursa`/`recursa-codegen` and declare
`framing(island = ..., boundary = SEMI)`: the pg-sql build script panics in
`recursa-codegen/src/generation/explorer.rs:3194`
(`explorer_content_token_schema_static`,
"typed explorer target retains its content token") while rendering the
generated recovery plan.

Root cause: `explorer_token_plans` (explorer.rs:445-452) maps each lexical
kind to at most one semantic target with
`parser_targets.iter().find(|target| target.base_kind == kind.id)`. When
several content-token parser targets share one base kind, only the first
target's `ContentTokenId` enters `ExplorerTokenPlan.semantic`. The lookups
keyed by `ContentTokenId` (`render_token_explorer`, explorer.rs:1545-1550,
and `explorer_content_token_schema_static`, explorer.rs:3186-3197) then fail
for every other target. pg-sql's admission model makes this unavoidable:
`ColId`, `NonReservedWord`, `ColLabel`, `BareColLabel`, and the other
admission types deliberately share one canonical identifier content base
(`src/tokens.rs`, "one canonical content base").

Minimal fixture: a grammar with `framing(island = Item, boundary = SEMI)`
and two declared semantic targets on one pattern reproduces the exact
panic. The panic stays even when no Node references the second target.
Remove the second declaration and generation succeeds.

```rust,ignore
#[derive(recursa::Node)]
pub enum Word<'input> {
    Text(#[lex(pattern = r"[a-z_][a-z0-9_]*")] WordText<'input>),
}
#[derive(recursa::Node)]
pub enum OtherWord<'input> {
    Text(#[lex(pattern = r"[a-z_][a-z0-9_]*")] OtherWordText<'input>),
}
```

Suggested fix direction (in Recursa, not here): the schema wanted at both
panic sites is kind-level. Resolve `ContentTokenId -> parser target ->
base_kind -> explorer_token_schema_static(kind_index)` instead of searching
`ExplorerTokenPlan.semantic`, or store the full set of semantic targets per
kind.

### Gap 2: a missing final boundary always erases the document

`frame_document` (`recursa-core/src/framing.rs:718-741`) sets
`recovered = true` for any island that reaches EOF without the boundary
token, even when the island parsed strictly and consumed the complete
suffix. The result is `FrameResult::Recovered` with the RCA5002 diagnostic
"framing island lacks its required boundary; source ownership failed
closed", and the strict values are erased. PostgreSQL's `RAW_PARSE_DEFAULT`
accepts an optional final semicolon (`SELECT 1` is a valid document), so the
optional-final-semicolon acceptance gate of #10 cannot pass until framing
supports a complete final island at EOF without its boundary.

### Validated design for the unblocked retry

- Island: a nullable Node `SqlDocumentItem { statement: Option<Statement> }`
  with `framing(island = ast::file::SqlDocumentItem, boundary = SEMI)`.
  The fixture proves empty (`;`), consecutive-empty (`;;`), leading-empty,
  and mixed documents frame as `Complete` with empty islands, and that
  recovery replay of empty islands adds no spurious diagnostics. Empty
  statements stay provenance occurrences and stay out of the semantic list.
- Empty, trivia-only, and comment-only documents are `Complete` with one
  gap part; `render_exact` and the ownership partition hold on CRLF,
  missing-final-newline, and multibyte sources.
- Boundary spellings inside closed regions do not split islands; lexical
  failures and unclosed regions recover with "skipped unexpected input";
  `put 'one' put 'two'`-style input fails closed with RCA5002 plus an
  `Unresolved` suffix part.
- Provenance needs no grammar-wide `spans` change: framing parses islands
  spanned, so `Parsed::source`/`source_bounds` are `Some` under the default
  optional capture mode.
- No recursa#93 trivia-retention opt-in is needed: framing gap parts give
  right-owned inter-item trivia and the EOF gap directly.
- The grammar-root re-export of a function
  (`pub use document::parse_sql`) fails selected-tree resolution (RCA2012);
  re-export types only, and reach the function through its module.
- API shape drafted and type-checked up to the generation panic:
  `document::parse_sql(&str) -> Result<SqlDocument, SqlParseError>` with
  `SqlParseError::{Recovered(SqlRecovery), Fatal(FrameError)}`;
  `SqlDocument::{source, render_exact, statements, items, occurrences,
  eof_trivia, part_spans}` over `CompleteFrame<SqlDocumentItem>`;
  `SqlRecovery` exposes only the grammar-erased surface.
